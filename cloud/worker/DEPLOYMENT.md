# Cloudflare deployment

Rucola keeps local Worker development separate from remote deployment resources.
The checked-in `wrangler.jsonc` is local/test-only. Remote deployment configuration is generated by `scripts/render-deploy-config.mjs` from the selected environment and its real D1 ID.

## Remote resources

| Environment | Worker | D1 | R2 | Rate-limit namespace |
| --- | --- | --- | --- | --- |
| dev | `rucola-cloud-dev` | `rucola-dev` | `rucola-media-dev` | `910001` |
| production | `rucola-cloud` | `rucola-prod` | `rucola-media` | `910002` |

The two environments intentionally use separate D1 and R2 resources. Rate-limit namespaces are also separated so counters do not overlap.

## Create Cloudflare resources

Authenticate locally with Wrangler:

```bash
npx wrangler login
```

Create the development D1 database in the EU:

```bash
npx wrangler d1 create rucola-dev --location weur --jurisdiction eu
```

Create the development R2 bucket in the EU:

```bash
npx wrangler r2 bucket create rucola-media-dev --location weur --jurisdiction eu
```

Repeat with `rucola-prod` and `rucola-media` when production is needed.

Keep the D1 UUID printed by `wrangler d1 create`; it is required by the deployment workflow. R2 bindings use the bucket name and do not need a bucket ID.

## Local validation

From `cloud/worker`:

```bash
npm ci
npm run typecheck
npm test
```

For a remote environment, set the D1 ID and render a temporary config:

```bash
RUCOLA_DEPLOY_ENV=dev \
RUCOLA_D1_DATABASE_ID="<DEV_D1_UUID>" \
npm run render:deploy-config
```

Inspect `.wrangler.deploy.jsonc` before doing anything remote.

## Apply migrations and deploy manually

```bash
npx wrangler d1 migrations apply rucola-dev --remote --config .wrangler.deploy.jsonc
npx wrangler deploy --config .wrangler.deploy.jsonc --strict
```

The production equivalents use `RUCOLA_DEPLOY_ENV=production` and `rucola-prod`.

## GitHub Actions

The `Cloud Worker` workflow runs typecheck and tests for normal pushes and pull requests. A manual `workflow_dispatch` can deploy either `dev` or `production`.

Configure these GitHub secrets for the selected GitHub Environment (`dev` or `production`):

- `CLOUDFLARE_ACCOUNT_ID`
- `CLOUDFLARE_API_TOKEN`
- `RUCOLA_D1_DATABASE_ID`

The Cloudflare token should be scoped to the account used by Rucola. The deployment needs Worker Editor access; the migration step also needs permission to modify the selected D1 database.

For production, configure GitHub Environment protection with a required reviewer before using the production deploy option.

## Health checks

After deployment, verify:

```text
GET /health
GET /health/schema
```

Both endpoints intentionally expose only service/schema health information, not message data.

## Security

Do not put the Cloudflare API token, D1 UUID, or any other credentials in the repository. The generated `.wrangler.deploy.jsonc` is ignored by Git and must remain a local/CI artifact.
